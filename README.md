# Аналитика задач Jira на Kotlin

Приложение получает задачи проекта через Jira Server/Data Center REST API v2 и создаёт самостоятельный HTML-отчёт с шестью видами графиков: время до закрытия, время в каждом состоянии, задачи по дням и накопительный итог, топ 30 исполнителей и репортёров, залогированное время закрытых задач и распределение по приоритетам. Для каждого состояния выводится отдельная гистограмма.

## Требования

JDK 22 для сборки и запуска, Gradle Wrapper для сборки. Отдельно устанавливать Kotlin не требуется. При первой сборке нужен доступ к Maven Central и Gradle Plugin Portal для загрузки зависимостей. Для построения отчёта нужен доступ к Jira и права на чтение задач и их истории.

## Сборка и запуск

1. Отредактируйте `config/app.properties`: `jira.baseUrl`, `jira.project`, `report.zone`, `report.output`.
2. Если сервер требует авторизацию, задайте `JIRA_TOKEN`. Для Basic Auth дополнительно задайте `JIRA_USER`; без имени используется Bearer token. Не сохраняйте токен в Git.
3. Выполните `./gradlew.bat test distZip` в Windows или `./gradlew test distZip` в Linux/macOS.
4. Распакуйте `build/distributions/jira-analytics-kotlin.zip`. Из корня распакованного дистрибутива запустите `run.bat` или `./run.sh`.
5. Откройте `report/index.html` (или каталог, указанный в `report.output`). Отчёт работает без подключения к сети после генерации.

Для запуска непосредственно из исходников: `./gradlew.bat run --console=plain --args="config/app.properties"`. Команда `run` компилирует и запускает приложение, но не выполняет тесты. Для тестов отдельно запустите `./gradlew.bat test`; для сборки и проверки вместе — `./gradlew.bat test distZip`.

По умолчанию `jira.maxIssues=100` и `jira.sortOrder=DESC`: отчёт строится по 100 самым новым задачам проекта. Это быстрая проверка, выборка явно подписана в отчёте. Для анализа всего проекта задайте `jira.maxIssues=0`. `jira.pageSize` задаёт размер одного запроса к поиску Jira, а не число задач в отчёте. `jira.sortOrder=ASC` выбирает старые задачи первыми, `DESC` — новые. `jira.detailConcurrency` ограничивает число одновременных запросов за историей закрытых задач; разумное значение — 4, слишком высокое может перегрузить Jira или вызвать ограничения запросов. Во время загрузки программа выводит прогресс; файл `report/index.html` появляется после завершения всей выборки.

## Методика расчёта

- Закрытой считается задача с заполненным `resolutiondate`. Время до закрытия измеряется от `created` до `resolutiondate`.
- Время состояния восстанавливается по истории изменений поля `status`, от создания до закрытия. Повторные посещения суммируются. Если Jira вернула неполную историю, приложение сообщает об ошибке, чтобы не строить неверный график.
- Залогированное время берётся из поля `timespent` (сумма worklog в секундах); отсутствие записи считается нулём.
- Для пользователей отдельно подсчитываются роли исполнителя и репортёра. Если один пользователь выполняет обе роли в задаче, обе серии получают по одному значению. Топ 30 сортируется по сумме двух ролей.
- Степень серьёзности соответствует полю Jira `priority`. Дневные группы считаются в часовом поясе `report.zone`, включая дни без событий.
- Ширина интервала гистограммы задаётся `report.binHours`; при большом диапазоне автоматически увеличивается, чтобы было не более примерно 40 интервалов.

Тесты: семь модульных проверок расчёта, проверка HTML-отчёта и интеграционный тест клиента с локальным HTTP-сервером. Живое подключение к Apache Jira зависит от доступности сервера и его прав доступа.
